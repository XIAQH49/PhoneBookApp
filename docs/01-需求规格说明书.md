## 1. 项目概述

### 1.1 背景

内部业务中存在定期"外呼名单"工作模式：内网系统导出一张 Excel 大表（2000+ 条且持续增长），
表中按"责任人"列分派了每个员工需要拨打的名单。当前工作流是：看表格 → 手动拨号 → 回内网手动标记。

### 1.2 一句话定位

> 从内网导入外呼名单文件，按责任人筛选出自己的任务，点击条目唤起系统电话并自动填入号码，
> 在本地标记"是否已打"，导出文件仅作本地留档/对照内网手动标记之用。

### 1.3 产品目标

- 把"看表格 + 拨号 + 记录进度"合为 APP 内一步完成；
- 数据完全本地，不联网、不上传，权限最小化；
- 支持 2000+ 条名单流畅使用，后续表格持续增长；
- **不负责回传内网**：内网台账由员工对照导出文件手动标记（业务现状，APP 不改变此流程）。

### 1.4 关键业务事实（约束后续所有设计）

1. 一个责任人只会拨打自己名下的名单，**本机不产生他人行的修改**；
2. 内网台账**不支持文件回传自动合并**，员工在内网系统里手动标记；
3. 电话号码不会出现多列，但**一个号码单元格内可能出现多个号码**，格式示例：
   `+86-19999999999`、`+86-19999999999/+86-19999999999`、
   号码后可能带括号注释如 `+86-19999999999（国内）`，注释内容不确定；
4. 名单持续增长（当前 2000+ 条），本机需长期可用。

## 2. 范围

### 2.1 首版（MVP）范围内

| 模块 | 说明 |
|---|---|
| 名单导入 | 系统文件选择器导入 .xlsx（主）/.csv（兼容），含编码识别与号码清洗（FR-1、FR-9） |
| 责任人筛选 | 按"责任人"列筛选自己的名单，记住上次选择；"未分配"只读展示（FR-3） |
| 名单列表 | 姓名、工号、手机、已打状态；状态筛选、关键字搜索、进度统计（FR-4） |
| 一键拨打 | 点击条目唤起系统电话自动填入号码；单格多号码时先选号（FR-5） |
| 状态标记 | 手动标记"已打/未打"，**允许直接撤销**（FR-6） |
| 结果导出 | 导出留档文件，写回"是否已打"，其他列原样保留；文件名带时间戳（FR-7） |
| 本地存储 | 名单、状态、配置全部本地持久化（FR-8） |

### 2.2 范围外（首版明确不做）

- ❌ 不做拨号盘/通话界面（仅唤起系统电话）
- ❌ 不接管系统来电/去电 UI，不是默认拨号器
- ~~不维护"是否打通/是否有意向"~~ → **M3 已纳入**（v0.4：FR-10/FR-11 可维护，见 5 节）
- ❌ 不做网络功能、云同步、账号体系；**不做回传内网的自动对接**
- ❌ 不做名单的编辑（含"未分配"行认领/修改责任人）与多人协作
- ❌ 不做通话录音

## 3. 术语定义

| 术语 | 定义 |
|---|---|
| 名单文件 | 内网导出的待拨打任务表格（xlsx/csv） |
| 责任人 | 表格"责任人"列的值，即需要执行拨打的员工（当前使用者） |
| 目标人 | 被拨打的姓名（表格"姓名"列），即接电话的对象 |
| 已打 | **拨出即算已打**：在 APP 中点击拨打并唤起系统电话（或手动勾选）即标记为已打；不要求接通 |
| 未分配 | 责任人列为空的行，首版只读展示，不可认领 |
| 留档导出 | 把带最新状态的名单导出为文件，用于本地备份或对照内网系统人工标记；**不回传内网** |

## 4. 用户与场景

### 4.1 用户角色

- **主用户**：内部外呼员工，手机为主要设备；每台手机一个使用人，只关心自己的责任人名单。
- 多台手机可各自导入同一份文件、各筛各的，**互不依赖、无文件回传合并**（内网侧仍为人工标记）。

### 4.2 核心流程

```
内网导出名单文件(.xlsx/.csv)
      → 传到手机 → APP 导入（编码识别 + 号码清洗）
      → 选择/确认责任人（记住上次）
      → 查看名单：进度统计(总/已打/未打/完成率) + 状态筛选 + 关键字搜索
      → 点击条目 → 选号(单格多号码时) → 唤起系统电话 → 拨完返回
      → 确认标记"已打"（可撤销）
      → 全部打完 → 导出留档文件(同格式, 原名+时间戳) → 对照内网人工标记
```

### 4.3 用户故事

- US-1：作为外呼员工，我要导入内网名单文件，以便在手机上查看自己的拨打任务。
- US-2：作为外呼员工，我要按责任人筛选名单，以便只看分配给自己的条目。
- US-3：作为外呼员工，我要点击一条名单就跳出系统电话并自动填入号码（单格多号码时可选择），以便不用手动输号。
- US-4：作为外呼员工，我要标记/撤销已打，以便随时知道哪些还没打。
- US-5：作为外呼员工，我要导出带最新状态的文件，以便留档并对照内网手动标记台账。

## 5. 功能需求

> 验收标准（AC）为"可测试、可判定"的描述，用于后续开发与验收。

### FR-1 名单文件导入

- 通过系统文件选择器选择 .xlsx / .csv 文件（自动识别格式）。
- **编码识别**：CSV 自动识别 UTF-8（含 BOM）与 GBK/ANSI（评审 P1-5），识别失败时提供手动指定编码重试，避免中文乱码。
- 解析表格，自动识别列（责任人、姓名、工号、手机、是否已打、是否打通、是否有意向），
  未识别的列**原样保留**，导出时不能丢失。
- 导入过程显示进度与耗时；解析在后台执行，不阻塞 UI。
- **AC**：导入含 2000 行 8 列的 xlsx 后，列表可见全部 2000 条且字段与表格一致。
- **AC**：导入含未知列的表格后，导出文件仍包含这些未知列且内容不变。
- **AC**：导入 GBK 编码的 CSV，中文内容无乱码。

### FR-2 重复导入合并（评审 P0-2 决议）

- 默认**合并模式**，规则如下：
  1. 行匹配键：优先"工号"，无工号或为空时按"姓名+手机"匹配；
  2. **已打状态取"或"**：本机或新文件任一为已打，合并后即为已打（本机拨打记录不丢、避免重复拨打）；
  3. 其他字段以新文件为准；
  4. 本机没有修改过的他人行，等效于直接以新文件为准（符合业务事实 1.4-1）；
  5. 新增行直接加入，新文件中消失的行保留本机数据并标记为"文件中已移除"。
- 提供**覆盖模式**选项：清空本地数据后全量导入（需二次确认）。
- **导入值判定规则**（评审 P1-6）："是否已打"列以下值判定为已打：
  `是 / 已打 / 已拨打 / √ / ✓ / 1 / true / TRUE / Y / YES / 完成`；
  判定为未打：`否 / 未打 / 空 / 0 / false / N / NO`；其他无法识别的值原样保留并归为未打（导出时原样处理）。
- **v0.4 扩展**：通用状态判定表（打通/意向复用）在 P1-6 基础上增加真值 `有 / 有意向 / 打通`、假值 `无 / 无意向`；"是否打通/是否有意向"列按同一机制判定，原值保留在 raw_data 中。
- **AC**：同一文件导入两次后不产生重复条目。
- **AC**：本机已标记已打的行，导入"该行未打"的新文件后，合并结果仍为已打。

### FR-3 责任人筛选与记忆

- 导入后自动提取"责任人"列的去重值列表。
- 启动时默认使用上次选择的责任人；可搜索、可切换。
- 列表**仅显示当前责任人 + "未分配"**两个范围的并集（可单独切到"未分配"查看）。
- 首版只读：不可修改责任人、不可认领"未分配"行；"未分配"列表页给出提示"请联系内网修正责任人"（评审 P2-12）。
- **AC**：重启 APP 后仍停留在上次选择的责任人名单。

### FR-4 名单列表与进度统计

- 每条目显示：姓名、工号、手机（多号码时显示"手机 ×N"）、已打状态徽标。
- 状态筛选：全部 / 未打 / 已打。
- 关键字搜索：匹配姓名、工号、手机号（实时过滤）。
- 顶部统计：**总条数 / 已打数 / 未打数 / 完成百分比**（评审 P2-9）。
- 点击条目进入详情：详情展示该行所有列（含打通/意向等原始值；其中 已打/打通/意向 三列可勾选维护，见 FR-6/FR-10/FR-11），并列出该行全部号码供拨号。
- **AC**：搜索"138"时仅显示手机号含"138"的条目；切到"未打"仅显示未打条目。
- **AC**：标记完成后统计条数与百分比即时更新。

### FR-5 一键拨打（v0.3：唤起系统拨号应用）

- 列表与详情页均有拨打按钮。
- **号码来源**：取"手机"列，经 FR-9 清洗后的号码列表：
  - 仅 1 个号码：弹确认框（显示姓名+号码）→ 确认 → 唤起系统电话；
  - 多个号码：先弹出号码选择列表 → 选定后唤起系统电话。
- **唤起方式（v0.3 用户拍板）**：通过 want `ACTION_DIAL`（ohos.want.action.dial）+ `tel:` URI 唤起系统电话应用并自动填入号码；
  **不申请 PLACE_CALL 权限、不直接外呼**；设备无可用拨号应用时，号码自动复制到剪贴板并提示手动粘贴拨打（兜底）。
- **确认框可关闭**（评审 P2-8）：提供"不再提示"勾选，勾选后后续点击直接拨号；设置页可重新开启。
- APP 不做通话 UI；唤起拨号返回 APP 后，该条目出现"是否已拨打？"提示，一键标记已打（拨出即算，见术语）。
- **AC**：点击拨打后系统拨号界面出现且号码已自动填入（含 `+86-` 前缀号码），无需手动输号。
- **AC**：单格多号码条目点击拨号时先出现号码选择列表。
- **AC**：无拨号应用时提示"号码已复制"，剪贴板内容为完整号码。

### FR-6 状态标记

- 列表支持一键勾选"已打/未打"，**允许直接撤销，无需二次确认**（评审决议 R-3）。
- 状态即时本地持久化，杀进程/重启不丢失。
- **AC**：标记 50 条已打后重启 APP，状态全部保留；撤销 10 条后再重启，同样保持。

### FR-10 是否打通维护（v0.4 新增，M3）

- 详情页在"是否打通"列提供勾选/撤销开关（只读展示改为可维护），与"是否已打"同一交互形式；
- 状态即时本地持久化（call_status 状态键 connected，复用 6.2 扩展模型），杀进程/重启不丢失；
- 列表与统计不增加打通维度的展示（保持首版界面简洁，仅详情页维护）；
- 重复导入合并时**取"或"**（R-8）：本机或新文件任一为"打通"，合并后即为打通（打通为终态事实，避免本机维护结果被旧文件覆盖丢失）；
- **AC**：详情页勾选"是否打通"→ 杀进程重启 → 详情页仍为打通；重复导入该行"未打通"的新文件 → 仍为打通。
- **AC**：导出文件"是否打通"列写回"是/空"（或沿用原格式，见 FR-7/R-9），其余行与原文件一致。

### FR-11 是否有意向维护（v0.4 新增，M3）

- 详情页在"是否有意向"列提供勾选/撤销开关，行为与 FR-10 一致（状态键 intention）；
- 值判定兼容意向惯用词（有/有意向 → 真；无/无意向 → 假），与通用判定表合并（见 FR-2 判定规则扩展）；
- 重复导入合并取"或"（R-8）；
- **AC**：详情页勾选"是否有意向"→ 重启后保持；重复导入"无意向"的新文件 → 仍为有意向。
- **AC**：导出文件"是否有意向"列写回沿用原格式（是/空、1/空 或 有/空），其余行与原文件一致。

### FR-7 结果导出（留档）

- 导出定位：**本地留档 / 对照内网系统人工标记**，不涉及回传合并（业务事实 1.4-2）。
- 导出范围：默认**当前责任人的行 + 未分配行**，可切换为"全表导出"。
- 写回"是否已打"列：已打 → "是"，未打 → 空；**若原文件该列存在既有值格式（是/否、1/空、√ 等），自动沿用**（评审决议 R-5）。
- 格式与原文件一致（xlsx 导 xlsx / csv 导 csv）；csv 使用 UTF-8 BOM 保证 Excel 中文不乱码。
- 文件名规范（评审 P2-10）：`原名_导出时间戳.扩展名`（如 `外呼名单_20250115_1530.xlsx`）。
- 通过系统保存/分享接口产出文件。
- **AC**：导入→标记 3 条已打→导出，用 Excel 打开导出文件，仅这 3 条"是否已打"变为"是"（或沿用格式），其余行与原始文件一致（含未知列）。
- **AC**：导出的 csv 文件用 Excel 打开无乱码。

### FR-8 本地持久化

- 名单数据、拨打状态、配置（上次责任人、确认框开关、导出范围）均存本地关系型数据库（relationalStore）。
- 纯本地运行：不申请网络权限，无任何数据上传。
- **AC**：飞行模式下 APP 全部功能可用（除系统拨号本身）。

### FR-9 号码解析与规范化（评审 P1-4）

- 针对"手机"列单元格内容做清洗提取，规则：
  1. **多号码拆分**：按 `/`、`／`、`、`、`,`、`;`、`；`、空格、换行等分隔符拆分；
  2. **注释剥离**：`（）`、`()`、`【】`、`[]`、`《》` 等括号及其中内容忽略（仅影响解析，列表中显示仍保留原文）；
  3. **前缀与连接符**：`+86-`、`86-`、`0086-` 统一保留国家码形式 `+86`，号码内部 `-`、空格在拨号时去除；
  4. **科学计数法还原**：数字型单元格（如 `1.38E+10`）按原值还原为整数文本 `13800000000`；
  5. **有效性校验**：清洗结果为 7~15 位数字（含国家码）方视为有效号码；
  6. **兜底**：无法解析出有效号码时，显示原文并支持长按复制，由用户手动拨号。
- 拨打时统一使用规范化号码调用系统拨号（`+86` 前缀号码直接支持）。
- **AC**：`+86-19999999999（国内）` → 解析出号码 `+8619999999999`，显示原文不变。
- **AC**：`+86-19999999999/+86-13800000000` → 解析出 2 个号码，拨号时可选；同格内重复号码去重（仅保留首个）。
- **AC**：数字型 `1.38E+10` → 解析为 `13800000000`。

## 6. 数据模型

### 6.1 名单行字段（与表格列对应）

| 列名 | 类型 | 首版可维护 | 说明 |
|---|---|---|---|
| 责任人 | 文本 | 否 | 筛选维度；空值归入"未分配" |
| 姓名 | 文本 | 否 | 拨打对象 |
| 工号 | 文本 | 否 | 行匹配键（优先） |
| 手机 | 文本 | 否 | 原始文本原样保存；解析结果另存号码列表（FR-9） |
| 是否已打 | 布尔 | ✅ 是 | 可维护状态（状态键 called）；导入值判定见 FR-2 |
| 是否打通 | 布尔 | ✅ 是（M3） | 状态键 connected；导入判定+合并取"或"；导出写回 |
| 是否有意向 | 布尔 | ✅ 是（M3） | 状态键 intention；导入判定+合并取"或"；导出写回 |
| 其他未知列 | 文本 | 否 | 原样保留，导出不丢 |

### 6.2 可扩展状态设计（为后续预留）

- 状态列不写死：以"状态键 + 值"结构存储；M1 仅有 `called`（是否已打），
  **M3（v0.4）增加 `connected`（是否打通）与 `intention`（是否有意向）**，复用同一表
  （call_status，UNIQUE(row_id, status_key)），未改表结构、旧数据无损。
- 状态值导出时按"状态键 → 表格列"映射写回；各列值格式独立探测沿用（R-9）。

## 7. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-1 | 性能 | **量化指标**（评审 P1-7）：2000 条导入解析 ≤ 10s（含进度提示）；10000 条以内列表滚动无明显掉帧（懒加载）；关键字搜索过滤响应 < 300ms；状态标记写入即时生效 |
| NFR-2 | 隐私 | 完全本地存储；不申请网络权限；仅申请拨号所需权限；**首版列表仅展示当前责任人数据，他人行不可见**（评审决议 R-6） |
| NFR-3 | 兼容 | HarmonyOS NEXT 真机（模拟器不支持电话能力，电话链路必须真机验证） |
| NFR-4 | 界面 | 简洁现代，遵循 HarmonyOS 设计规范，跟随系统深/浅色；手机竖屏为主 |
| NFR-5 | 可靠性 | 导入中断/解析失败时本地已有数据不受影响；导出失败可重试；合并导入失败可回滚 |
| NFR-6 | 数据安全 | 导出文件与原始文件逐列对应，内容可审计；不包含本地配置等额外数据 |

## 9. 评审决议与开放问题

### 9.1 评审决议（v0.2 已拍板，共 7 项）

| 编号 | 议题 | 决议 |
|---|---|---|
| R-1 | 重复导入合并（原 OQ-1 / 评审 P0-2） | 合并模式；**已打状态取"或"**（本机或新文件任一已打即已打）；其他字段以新文件为准 |
| R-2 | 号码列（原 OQ-2） | 不会出现多列；单格可多号码、可带括号注释，由 FR-9 清洗，多号码时拨号前选择 |
| R-3 | 撤销标记（原 OQ-3） | 允许直接撤销，无二次确认 |
| R-4 | 导出范围（原 OQ-4 / 评审 P0-1） | **不回传内网**（内网人工标记），导出仅留档/对照；默认当前责任人+未分配，可选全表 |
| R-5 | 已打写入值（原 OQ-5） | 自动沿用原文件既有值格式，无格式时默认 是/空 |
| R-6 | 他人名单可见性（原 OQ-6 / 评审 P2-13） | 首版仅当前责任人；他人行本地保留但不可见；权限扩展留后续版本 |
| R-7 | 已打口径（评审 P0-3） | **拨出即算已打**；"是否打通/是否有意向"排期 M3 起维护（v0.4 已实施）；内网统计为人工流程，无自动对接依赖 |
| R-8 | 打通/意向合并语义（M3 拍板，类推 R-1） | 与已打一致**取"或"**：本机或新文件任一为真即真；打通/意向为终态事实，取"或"保证本机维护结果不被旧文件覆盖丢失 |
| R-9 | 打通/意向导出格式（M3 拍板，类推 R-5） | 各列独立探测原文件值形态并沿用：是/空（yes_no）、1/空（one_blank）、有/空（has_none，意向列惯用）；无法判定默认 是/空 |
