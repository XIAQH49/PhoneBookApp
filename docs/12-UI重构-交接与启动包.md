## 3. 新需求：UI 大重构（已与用户拍板，2026-08-27）

| 项 | 决策 |
|---|---|
| 版本定位 | 下一个大版本 = **UI 重构**（功能面已基本完备，不再做大功能迭代） |
| 风格 | **简洁现代风**：大留白、卡片化、圆角、轻拟态（参考主流效率类 App） |
| 范围 | **大重构**：信息架构允许调整（如底部 Tab 导航、合并页面），但功能与数据语义不变 |
| 痛点1 | 主页布局：顶部标题/统计/筛选/搜索/列表/四个按钮全堆在一屏 → 重构信息层级 |
| 痛点2 | 列表行：信息平铺、徽标生硬、拨号按钮突兀 → 姓名+号码主视觉、状态胶囊化 |
| 痛点3 | 详情页：表格式逐行展示简陋 → 分区卡片（基本信息/号码区/状态区/备注区） |
| 痛点4 | 设置/选择页：样式与主流程割裂 → 统一组件与配色 |
| 痛点5 | 整体配色/字体/间距不统一 → 建立设计令牌（色板/字号/圆角/间距），深浅色都走资源引用 |

## 5. 关键坑位清单（历次会话累积，新会话必读）

1. **签名**：CLI hvigor 无法解密 IDE 加密口令（Init keystore failed）；签名+安装统一走 DevEco Studio Run；
2. **CLI 测试限制**：hvigorw test 不解析 src/main 导入；CLI 逻辑验证以 tools/verify Node 套件为准，hypium 仅 IDE 内跑；
3. **拨号**：零权限方案 = startAbility(want viewData + tel:URI + entity.system.home) 唤起 com.ohos.contacts；不用 queryAbilityByWant（需权限且废弃）；
4. **ArkUI 状态**：子组件参数必须 @Prop/@Link；LazyForEach 全量刷新必须用"数据源版本号并入条目键"（onDataReloaded 对同键条目复用视图不重建）；
5. **Navigation**：宿主 onPageShow 在 NavDestination pop 时不触发；子页 pop 必须带 result 且 onBackPressed 拦截返回 true，宿主经 onPop 回调刷新；pop 过渡期间宿主 List 隐藏，刷新要延迟 ~400ms；
6. **冷启动**：DB 异步初始化需 DbHelper.ready() 等待 + 页面重试；
7. **合并语义**：状态（已打/打通/意向）取"或"；源文件内完全重复的行原样保留（对半去重只消除并发导入多出的那一份）；新文件缺失行标记 in_file=0，重现时按同键复活；
8. **导入并发**：ImportService 有全局串行队列 + BuiltinListService 单飞，勿绕过 importFromBytes 直接写库；
9. **DB 迁移**：DbHelper.doInit 内幂等迁移（PRAGMA table_info + ALTER + app_config 标记守卫），新表结构变更必须走同一模式；
10. **rawfile/名单.xlsx**：本地构建用、已 gitignore；测试样本在 samples/（2000行/26行重复工号/GBK/UTF8/M3_20行）；
11. **真机自动化**：hdc shell uinput 注入触摸 + uitest dumpLayout 拿控件树（文本+坐标）；截图对非多模态模型无用；Toast/系统弹窗/文件选择器是独立窗口，dumpLayout 抓不到，需用户目视确认；
12. **hilog**：本设备上应用自定义域日志不出现在 hdc shell hilog 流中（现象未解），诊断以 UI 行为证据为准；
13. **git 代理**：推送依赖本机 Clash for Windows（E:\Clash for Windows\Clash for Windows.exe，端口 7890），代理没开时 git push 失败；
14. **构建环境**：DEVECO_SDK_HOME=D:\DevEco Studio\sdk、JAVA_HOME=D:\DevEco Studio\jbr；构建目录 .hvigor/entry/build 勿提交；
15. **ArkTS 语法**：对象字面量必须对应显式声明的 class/interface（arkts-no-untyped-obj-literals）；SDK 调用点必须 try/catch 否则 may-throw 警告，构建门禁 0 警告。
