## 1. 拆分原则

1. 每任务 = 设计规格 12 节的一个模块单元，可独立开发、独立验证；
2. 每任务带**可测验收标准**，标准引用需求规格的 FR/AC 编号；
3. 任务按依赖链排序，T7（真机 spike）与 T3~T6 可并行；
4. 每个任务合入后必须通过 **构建门禁**（见下），全部任务完成后做 T14 整体验收。

### 1.1 构建门禁（每个任务完成时执行）

| 门禁 | 命令/方式 | 通过标准 |
|---|---|---|
| 编译 | DevEco 命令行 hvigor：`hvigorw assembleHap --mode module -p product=default -p buildMode=debug`（本机已验证可用） | 0 编译错误；警告逐条评估并登记 `docs/05-警告处置记录.md`（立即修复或明确排期） |
| 单测 | 本地 hypium LocalUnit / node 逻辑验证脚本 | 全部用例通过 |
| 静态 | 代码一致性检查（页面注册、权限、import 路径） | 无遗漏 |

## 2. 任务分解

### T0 工程配置与构建基线

- 依赖：无
- 内容：
  1. `module.json5` 增加 `ohos.permission.PLACE_CALL` 权限声明（设计 5.1）；
  2. `main_pages.json` 注册 ContactDetail / Settings / AssigneePicker；
  3. `string.json` 增加 `place_call_reason` 及界面文案；
  4. `EntryAbility.onCreate` 初始化数据库（DbHelper，幂等）；
  5. 跑通命令行构建基线；整理 AGC ACL 开通指引（真机调试前由用户操作）。
- 产出：module.json5、main_pages.json、string.json、EntryAbility.ets、docs 附 ACL 指引
- 验收：debug 构建通过；安装后权限弹窗文案正常显示

### T1 公共层与数据模型

- 依赖：T0
- 内容：`common/Constants.ets`（分隔符、状态键、配置键、值判定表）、`common/Logger.ets`（hilog 封装）、`model/CallRecord.ets`、`model/ImportMeta.ets`、`model/ColumnMapping.ets`
- 验收：类型定义与设计 3.1 表结构字段一一对应（人工走查）

### T2 数据库层

- 依赖：T1
- 内容：`DbHelper.ets`（建库建表、索引、幂等初始化）、`MetaDao.ets`、`CallListDao.ets`（分页/搜索/统计/键快照）、`StatusDao.ets`（状态双写事务）、`ConfigDao.ets`
- 验收（集成测试，hypium ohosTest）：
  - 建表幂等：二次 init 不报错；
  - 状态双写：setCalled 后 call_status 与 call_list.called 一致（设计 3.2）；
  - 分页：LIMIT/OFFSET 结果正确；统计 COUNT 正确；搜索 LIKE 命中；
  - 导入失败回滚：事务中途抛错后数据无残留（NFR-5）

### T3 号码解析（FR-9）

- 依赖：T1（不依赖 DB）
- 内容：`service/NumberParseService.ts`——解析状态机 S0~S6（设计 4.5）；纯逻辑文件（.ts，可用 Node 直接跑验证）
- 验收（单测，覆盖设计 4.5 全部样例 + 边界）：
  - `+86-19999999999（国内）` → `["+8619999999999"]`
  - `+86-19999999999/+86-19999999999` → 2 个号码
  - 数字型还原 `1.38E+10` → `["13800000000"]`
  - `138 8888 8888（转123）` → `["+8613888888888"]`
  - 座机 `0755-88888888` → `["075588888888"]`
  - 全无效输入 → 空数组（UI 走复制兜底，FR-9-6）

### T4 合并与已打值映射（FR-2 / R-1）

- 依赖：T1
- 内容：`service/MergeService.ts`——合并计划计算（设计 4.2：键规则、状态取或、消失行标记）+ 已打值判定/导出格式探测（设计 3.3）
- 验收（单测）：
  - 工号相同 → 匹配；工号空 → 姓名+手机 hash 匹配；
  - 本地已打 + 新文件未打 → 合并后已打（状态取或）；
  - 本地未打 + 新文件已打 → 合并后已打；
  - 新行 → insert；消失行 → 标记 in_file=0；
  - 判定表：`是/√/1/true/YES/已打` → true；`否/空/0/N/NO` → false；未知值 → false 且原值保留；
  - 格式探测：含"是" → yes_no；含"1/√" → one_blank

### T5 CSV 服务（FR-1 部分 / 设计 4.1）

- 依赖：T1
- 内容：`service/CsvService.ts`——编码检测（BOM → utf-8；严格 utf-8 解码失败回退 gbk，检测函数可注入解码器）、RFC4180 解析（引号转义/CRLF/分隔符自动识别）、写出（UTF-8 BOM）
- 验收（单测）：
  - utf-8 与 gbk 编码样本中文均正确；
  - 含逗号/引号/换行字段解析正确；
  - 写出文件带 BOM，Excel 打开不乱码（T-2 真机样本回归）

### T6 导入编排（FR-1 / FR-2）

- 依赖：T2、T3、T4、T5
- 内容：`service/ImportService.ets`——picker 选文件 → 格式识别 → 解析 → 列识别（包含匹配，兼容"是否已打（是/否）"表头）→ 逐行清洗 → MergeService 计划 → 单事务入库 → meta 切换 → 进度回调（每 200 行让出主线程）
- 验收（集成测试 + 真机）：
  - 导入 2000 行样例：全部入库、列识别正确、未知列进入 raw_data；
  - 重复导入：状态取或、无重复行（FR-2 AC）；
  - 中途失败：回滚且旧数据完好（FR-1 失败处理）

### T7 真机 Spike（T-1 / T-3，可与 T3~T6 并行）

- 依赖：T0（可安装调试包）
- 内容：
  1. T-1：ohpm 引入 `@ohos/xlsx`，最小 demo 解析 2000 行样例并写回，真机测性能与兼容性；
  2. T-3：真机最小 demo 验证 `call.makeCall('+86...')` 行为（拨号界面/号码完整性）。
- 验收/决策：
  - T-1 通过（解析 <10s、导出 PC Excel 可打开）→ T8 启用，M1 含 xlsx；不通过 → M1 交付 CSV 闭环，xlsx 顺延 M2（失败预案见设计 9 节）；
  - T-3 通过 → 保留 `+86` 规范化拨号；不通过 → 拨号前统一去国家码

### T8 XlsxService（条件任务）

- 依赖：T7（T-1 通过）
- 内容：`service/XlsxService.ets`——解析（原始值类型保留、数字型还原）、写出（含列顺序组装）
- 验收：与 T5 同标准的 xlsx 用例；导出文件 PC Excel 打开、中文正常、未知列保留

### T9 拨号服务与权限（FR-5）
