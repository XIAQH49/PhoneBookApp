## 3. 数据设计

### 3.1 表结构（relationalStore，库名 `phonebook.db`）

**import_meta（导入元信息）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK AUTOINCREMENT | |
| file_name | TEXT | 原文件名（导出命名用） |
| file_format | TEXT | `xlsx` / `csv` |
| file_encoding | TEXT | `utf-8` / `gbk` |
| column_mapping | TEXT(JSON) | 已知列名→业务字段映射，如 `{"assignee":"责任人","name":"姓名","empNo":"工号","phone":"手机","called":"是否已打"}` |
| all_columns | TEXT(JSON) | 原表**全部列名及顺序**（导出组装用，未知列在此） |
| called_value_format | TEXT | 已打列导出值格式：`yes_no` / `one_blank` / `custom` |
| connected_value_format | TEXT | M3：打通列导出值格式（`yes_no` / `one_blank` / `has_none`） |
| intention_value_format | TEXT | M3：意向列导出值格式（同上） |
| active | INTEGER | 仅一份为 1（生效数据集） |
| imported_at | INTEGER | 毫秒时间戳 |

**call_list（名单行）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK AUTOINCREMENT | |
| meta_id | INTEGER | 归属导入批次 |
| row_no | INTEGER | 原文件行序（导出排序用） |
| row_key | TEXT | 合并匹配键：`E:{工号}` 或 `H:{hash(姓名+手机原文)}` |
| assignee | TEXT | 责任人（空 = 未分配） |
| name | TEXT | 姓名 |
| emp_no | TEXT | 工号 |
| phone_raw | TEXT | 手机列原文（列表展示原文） |
| phone_numbers | TEXT(JSON) | FR-9 清洗结果 `["+8619999999999", ...]` |
| called | INTEGER | **冗余缓存列**（0/1），与 call_status 双写，列表查询/筛选免联表 |
| raw_data | TEXT(JSON) | 该行**全部原始列值**（含未知列），导出原样写回 |
| in_file | INTEGER | 1=新文件中存在；0=已从新文件消失（FR-2 保留本机数据） |
| created_at / updated_at | INTEGER | 时间戳 |

索引：`idx_assignee(assignee)`、`idx_status(assignee, called)`、`idx_key(row_key)`、`idx_meta(meta_id)`。

**call_status（状态键值表，6.2 扩展模型）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK AUTOINCREMENT | |
| row_id | INTEGER | FK → call_list.id |
| status_key | TEXT | `called`（是否已打）/ `connected`（是否打通，M3）/ `intention`（是否有意向，M3） |
| value | INTEGER | 0/1 |
| updated_at | INTEGER | 毫秒时间戳 |

约束：`UNIQUE(row_id, status_key)`。

**app_config（配置键值）**

| key | 默认 | 说明 |
|---|---|---|
| last_assignee | 空 | 上次责任人（R: FR-3） |
| confirm_before_call | `1` | 拨号前确认框开关（FR-5"不再提示"） |
| export_scope | `mine` | 导出范围 `mine`（当前责任人+未分配）/ `all` |

### 3.2 状态读写规则（M3 修订）

- **called（已打）**：标记/撤销时 `StatusDao.setCalled(rowId, value)` 在同一事务内
  1) upsert `call_status(called)`；2) 同步 `call_list.called` 缓存列（列表查询/筛选免联表）。
- **connected / intention（M3）**：仅写 `call_status`（`StatusDao.setValue(rowId, key, value)`），
  不加 call_list 缓存列（列表不展示、不筛选这两个维度）；详情页按行读取，导出批量读取。
- 一致性断言（ohosTest）：called 双写一致；connected/intention upsert 幂等且可回读。

### 3.3 "是否已打"值判定与导出映射（FR-2 / R-5）

导入判定表（Constants）：

```
已打:   是 / 已打 / 已拨打 / √ / ✓ / 1 / true / TRUE / Y / YES / 完成
未打:   否 / 未打 / 空串 / 0 / false / N / NO
无法识别: 视为未打，原值保留在 raw_data 中，导出原样处理
```

导出格式探测：导入时扫描原列**已打行**的值形态：
- 出现过 `是` → `yes_no`：已打=`是`、未打=空
- 出现过 `1`/`√` → `one_blank`：已打=`1`、未打=空
- 无法判定 → 默认 `yes_no`

**M3 通用状态判定表（StatusValue，打通/意向复用）**：

```
真值:   是 / 已打 / 已拨打 / √ / ✓ / 1 / true / TRUE / Y / YES / 完成 / 有 / 有意向 / 打通
假值:   否 / 未打 / 未拨打 / 0 / false / FALSE / N / NO / 无 / 无意向
无法识别: 视为假，原值保留在 raw_data 中
```

各状态列**独立**探测导出格式（R-9）：
- `yes_no`（出现过 是/否）→ 真=`是`、假=空
- `one_blank`（出现过 1/√/✓）→ 真=`1`、假=空
- `has_none`（出现过 有/无，意向列惯用）→ 真=`有`、假=空
- 无法判定 → 默认 `yes_no`

## 4. 关键流程设计

### 4.1 导入流程（FR-1 / FR-2）

```
用户点[导入]
 → DocumentViewPicker.select（过滤 .xlsx/.csv）
 → 读取文件为 ArrayBuffer（fs.openSync(uri)）
 → 格式识别：扩展名 + 魔数（xlsx 实为 zip: PK\x03\x04）
 → 解析：
     CSV → CsvService：编码检测(BOM→utf-8；无BOM→utf-8 严格解码失败回退 gbk)
        → RFC4180 解析（引号转义、CRLF/LF、分隔符自动识别 , / \t）
     XLSX → XlsxService（@ohos/xlsx）→ sheet_to_json(raw)，保留原始值类型
 → 列识别：表头与已知列名做包含匹配
    （"是否已打"兼容表头如"是否已打（是/否）"；未匹配列全部进入 all_columns）
 → 逐行：FR-9 号码清洗 → 生成 row_key → 组装 raw_data
     → 状态判定（通用判定表）：called / connected / intention 三列各判布尔
     → 三列各自探测导出值格式（R-9，存入 import_meta）
 → MergeService 合并（见 4.2），单事务入库
 → 切换 import_meta.active、刷新责任人列表与页面
 → 进度：每 200 行回调一次进度；解析分段 await 让出主线程
失败处理：整个导入在事务中，失败回滚，本地旧数据不受影响（NFR-5）。
```

### 4.2 合并算法（MergeService，R-1）

```
输入：新行集 N（本次解析结果）、本地行集 L（active 批次）
1. 键：emp_no 非空 → "E:"+emp_no；否则 → "H:"+hash(name + '|' + phone_raw)
2. N 中每行 n：
   - 命中 L 中同键 l：
       called_merged = l.called OR n.called          ← 状态取"或"（R-1）
       connected_merged = l.connected OR n.connected  ← M3 取"或"（R-8）
       intention_merged = l.intention OR n.intention  ← M3 取"或"（R-8）
       raw_data / phone_numbers / 其他字段 = n 的值   ← 以新文件为准
       in_file = 1
   - 未命中：插入 n（三状态 = n 的文件判定值）
3. L 中键不在 N 的行：in_file = 0（保留，列表标注"文件中已移除"）
4. 单事务提交；异常整体回滚
```

### 4.3 拨号流程（FR-5，v0.3：唤起系统拨号应用）

```
列表/详情点[拨打]
 → NumberParseService 结果：
     0 个号码 → 提示"未识别到有效号码"，提供复制原文
     1 个号码 → confirm_before_call=1 ? 确认弹窗 : 直拨
     N 个号码 → NumberSheet 半模态选号 → 按上述逻辑
 → CallService.openDialer(context, normalizedNumber)
     want ACTION_DIAL(ohos.want.action.dial) + uri 'tel:<号码>' → context.startAbility
     成功 → 系统拨号界面带号出现 → 返回 APP 后条目提示"是否已拨打？"→ 一键标记（拨出即算，R-7）
     失败（无拨号应用）→ 号码复制剪贴板 + 提示手动粘贴拨打
```

`openDialer` 使用 want `ACTION_DIAL` + `tel:` URI（**无需 PLACE_CALL 权限，v0.3 用户拍板**）；
号码为清洗后的规范化形式（`+8619999999999`），设置页"拨号前去除 +86"兼容开关可降级为 11 位（T-3 真机验证）。

### 4.4 导出流程（FR-7）

```
用户点[导出] → 弹层选范围（默认 export_scope）
 → 取 import_meta（all_columns 顺序 + called/connected/intention 三个 value_format）
 → 组装行：raw_data 各列原值；"是否已打/是否打通/是否有意向"三列按各自格式写入
   （真=是/1/有，假=空；列不存在则跳过，M3）
 → 仅导出范围内行（mine：assignee=当前责任人 或 空）
 → 写出：xlsx（@ohos/xlsx）或 csv（RFC4180 + UTF-8 BOM）
 → 文件名：原名_yyyyMMdd_HHmm.扩展名
 → DocumentViewPicker.save 保存；失败回退：写入沙箱 + systemShare
```

### 4.6 原始内置文件导出（FR-12，v0.6）

```
主页点[导出原始文件]
 → BuiltinListService.exportBuiltin(context)
     findBuiltin → 找到 名单.xlsx/名单.csv（不存在则提示指引）
 → resourceManager.getRawFileContent(name) 取原始字节
 → 文件名：原名_原始_yyyyMMdd_HHmm.扩展名（复用 ExportLogic.buildFileName）
 → DocumentViewPicker.save 保存 → ExportService.writeUri 写字节
 → Toast 结果
```

字节级原样写出（不经过解析/组装），保证与内置文件一致（含未知列与重复行）。

### 4.5 FR-9 号码解析状态机（NumberParseService）

```
输入：cellText（原文）、cellType（xlsx number/string）
S0 数字还原：xlsx 数字型整数 → 无科学计数法的字符串
   （11 位手机号 < 2^53，float64 无损；1.38E+10 → "13800000000"）
S1 注释剥离：扫描配对括号（）、()、【】、[]、《》及其内容，删除；
   未闭合括号视为注释直至行尾（仅保留括号前内容）
S2 拆分：按 / ／ 、 ， , ; ； \n \r \t 拆成候选段（空格不作为分隔符）
S3 段清洗：去首尾空白；移除段内空格、-、－（保留 + 与数字）
S4 前缀规范化：
   - ^\+?0{0,2}86[- ]?... → 国家码 86 → 统一 "+86"+其余数字
   - 11 位且 ^1[3-9]\d{9}$ → "+86"+号码
   - 其他 7~15 位纯数字 → 原样（座机/400）
S5 校验：^\+?\d{7,15}$ 为有效；按序去重
S6 输出：有效号码数组 + 解析失败标记（失败时 UI 显示原文 + 复制兜底）
```

单测样例（来自业务真实格式）：
- `+86-19999999999（国内）` → `["+8619999999999"]`
- `+86-19999999999/+86-13800000000` → 2 个号码（重复号码按序去重）
- `1.38E+10`（数字型） → `["13800000000"]`
- `138 8888 8888（转123）` → `["13888888888"]`（空格在 S3 移除）

### 5.1 module.json5 变更（v0.3）

- 深浅色：EntryAbility 已设 `COLOR_MODE_NOT_SET`（跟随系统）✓，页面颜色一律走资源引用，不做硬编码。

## 7. 性能设计（NFR-1 落点）

| 场景 | 方案 | 指标 |
|---|---|---|
| 列表 | LazyForEach + 分页查询（LIMIT 100/OFFSET），SQL 走 idx_assignee + idx_status | 1 万条滚动无明显掉帧 |
| 搜索 | SQL LIKE + 输入防抖 300ms | 过滤响应 <300ms |
| 统计 | `SELECT COUNT(*) GROUP BY called`（走 idx_status） | 即时 |
| 导入 | CSV 同步流式解析；xlsx 主线程分段 await（每 200 行让出一次）；T-1 验证是否上 taskpool | 2000 条 ≤10s（含进度提示） |
| 标记 | 单事务双写（3.2），批量勾选合并提交 | 即时生效 |

## 8. 错误处理与可靠性（NFR-5）

| 场景 | 处理 |
|---|---|
| 导入解析失败 | 事务回滚，Toast 具体原因；旧数据不受影响 |
| 编码识别失败 | 导入前提供编码选择（UTF-8 / GBK）重试入口 |
| 号码全部无法解析 | 条目可正常展示原文，拨号按钮提示复制（FR-9 兜底） |
| PLACE_CALL 被拒 | 引导去系统设置开启，提供复制号码替代 |
| 导出失败 | 重试；仍失败则改走"保存到应用沙箱 + 系统分享" |
| 空数据/未分配 | 空态视图 + 提示文案，不白屏 |

### 13.1 信息架构（拍板结论）

- **单页架构不变**：主页 Index + Navigation 压栈子页（ContactDetail / Settings / AssigneePicker）；
  底部为**悬浮胶囊操作按钮栏**（导入名单/内置名单/导出原始文件/导出结果），**不做多页 Tab**。
- 交互链路不变：onPop 刷新（延迟 400ms）、LazyForEach 数据源版本键、拨号唤起、导入合并语义均不动。

### 13.2 设计令牌（docs/14 第 2 节，落点为双套资源）

- 色板 12 令牌（primary/primary_soft/bg/card/text_primary/text_secondary/text_hint/success/warning/danger/divider/success_soft/warning_soft/danger_soft/bar_bg/shadow）→
  `resources/base|dark/element/color.json`，全部经 `$r('app.color.*')` 引用；
- 圆角（24/20/999/16vp）、间距（16/20/12/20vp）、字号（40/28/22/16/13fp）→ `float.json`；
- 阴影两档（card/raised，主色调低透明度光感阴影）→ `common/ThemeSpec.ets`（数值型参数，资源不支持阴影参数）；
- 动效曲线/时长/位移/缩放/错峰 → `common/MotionSpec.ets`（`@kit.ArkUI` 的 curves.springMotion / responsiveSpringMotion / interpolatingSpring）。
