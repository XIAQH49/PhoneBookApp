# v0.6 开发任务：PC 意图直达导入（bat 解析 Excel → hdc 意图传参 → APP 接收入库）

> 本文件是给 AI 开发者的任务提示词。你已了解本仓库代码结构（如不确定请先读 docs/09 交接包）。

## 背景与目标

内网环境：手机与 PC 无网络互通、无文件分享通道、USB 仅可用于开发者调试（hdc 通道可用）、
APP 已通过 IDE Run 安装。需求：**PC 端用 bat 脚本解析 Excel 名单，逐行分批通过
`hdc shell aa start` 的意图参数（Want parameters）推给手机 APP，APP 累积后走现有导入管线入库**。
这样每次换名单无需重新打包 APP、无需网络、无需文件传输。

## 技术方案（按此实现，如遇设备实测不符再调整并记录）

### 1. 通道与协议

- PC：`hdc shell aa start -b com.example.phonebookapp -a EntryAbility --pi ...`（**--pi 参数的确切语法
  未定**：先连 SGT-AL10 用 `aa start` 实测确定，支持 key/value 或 JSON 字符串两种候选，选定后写入文档；
  hdc 路径：`D:\DevEco Studio\sdk\default\openharmony\toolchains\hdc.exe`）
- 载荷格式（每批一个 intent）：
  ```json
  {
    "action": "import_rows",
    "transferId": "1699999999999",
    "batch": 1,
    "total": 20,
    "headers": ["责任人","姓名","工号","手机","是否已打","备注"],
    "rows": [["张三","客户1","E10001","+86-19999999999","",""], "..."]
  }
  ```
  - 载荷整体做 **base64(UTF-8 JSON)** 后放入单个参数，避免 shell 引号/长度问题；
  - 每批默认 **50 行**（实测单 intent 参数长度上限后微调）；
  - 同一 transferId 的批次数 = total；批次从 1 开始连续编号。
- APP 侧接收点：`EntryAbility.onCreate`（冷启动）与 `onNewWant`（热启动，默认 singleton 会回调）。
- 累积：按 transferId 存沙箱（`context.filesDir/intent_import/<transferId>/batch_<n>.json`）；
  仅保留最新 transferId（收到新 transferId 时清掉旧目录）。
- 完成判定：收到 batch==total 时，校验已收批次连续无缺；完整 → 触发导入；缺失 → 丢弃并 toast
  "接收不完整，请在 PC 端重发"。

### 2. 复用现有管线（关键：不新写解析/合并逻辑）

收到完整批次后，把 headers+rows **拼装成 CSV 文本**（复用 CsvService.toCsv），
再调用 `ImportService.importFromBytes(utf8Bytes, 'intent_import.csv')` —— 完整复用
解析（ImportLogic.prepare）、合并（MergeService，已打状态取"或"保留）、入库、元信息切换全链路。
注意：该导入**不写** `builtin_last_hash`（与内置名单相互独立）。

### 3. UI 反馈

- 导入成功后设置一个标记（建议 ConfigDao 键 `last_intent_import` = 行数+时间）；
- `Index.onPageShow` 检测该标记 → toast "已从内网导入 N 条" → `vm.reloadAssignee()` + `syncAll()` → 清除标记。

### 4. PC 端交付物（tools/intent_sender/）

- `send_list.bat`：入口脚本。参数：xlsx/csv 文件路径（缺省取同目录最新 .xlsx）；流程：
  1. 定位 hdc（优先 PATH，其次 DevEco 固定路径）；
  2. 调 `node --import ../verify/register.mjs sender.ts <文件>` 完成解析与分批（**直接 import
     entry 下的纯 TS：XlsxService/CsvService，与 APP 同一套解析代码**，表格→行数组）；
  3. 逐批生成 intent 参数（base64 载荷）并执行 `hdc shell aa start ...`；
  4. 打印进度与结果（每批成功/失败；total 批数）。
- `sender.ts`：解析+分批+base64+拼装 hdc 命令（node 直跑，依赖仓库现有 register.mjs 加载器）。

## 硬性约束（继承 docs/09 坑位清单）

- 只读复用现有解析/合并管线，禁止重写一套导入逻辑；
- 不申请任何新权限；不改动拨号/内置名单/清除/统计现有行为；
- CLI 无法签名 → 安装始终由 IDE Run 完成（bat 只用 hdc 发 intent，不负责安装）；
- ArkUI 状态注意 @Prop/@Link 与空态 layoutWeight 的既有约定；
- 若 `aa start --pi` 在该设备上完全不可用（语法全部失败），立即停止，把实测现象写进文档并汇报，
  不要擅自改走其他通道。
