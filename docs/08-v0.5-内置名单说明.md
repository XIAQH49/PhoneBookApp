# v0.5 内置名单功能说明

| 项 | 内容 |
|---|---|
| 版本 | v0.5（基于已验收 v0.3.4 开发） |
| 需求背景 | 内网"只能进不能出"：无法联网/回传，也无法便捷地传文件到手机 → 名单文件直接打进 APP 包内 |
| 命名约定 | `entry/src/main/resources/rawfile/` 下放 **`名单.xlsx`**（优先）或 **`名单.csv`** |
| 行为 | APP 启动自动检测内置文件**内容哈希**变化 → 变化即合并导入（已打状态取"或"保留，与手动导入同一套合并规则）；主页新增"内置名单"按钮可手动导入 |

## 使用流程（每次名单更新时）

1. 把内网导出的最新表格重命名为 `名单.xlsx`（或转成 `名单.csv`）
2. 覆盖到 `entry/src/main/resources/rawfile/`（参考同目录 `README.txt`）
3. DevEco Studio **Run**（重新打包安装）
4. APP 启动 → 检测到内容变化 → 自动导入并提示"内置名单已更新并导入"
5. 名单数据即最新，已打状态保留（按工号/姓名+手机合并）

## 验证要点（真机）

| 步骤 | 预期 |
|---|---|
| rawfile 放 `名单.xlsx` → Run | 启动后 toast"内置名单已更新并导入"，列表出现数据 |
| 不改文件再次冷启动 | 无提示、不重复导入 |
| 修改表格内容（如加一行）→ Run | 自动合并导入新内容，原有已打状态保留 |
| 主页点"内置名单" | 无变化提示"无变化"；有变化则导入 |
| rawfile 无名单文件 | 点"内置名单"提示命名与路径指引 |

## 技术要点

- 变更检测：内置文件字节的 FNV-1a 哈希存 `app_config.builtin_last_hash`，与上次比较（避免每次启动重复导入）；
- 导入复用 `ImportService.importFromBytes`（从 picker 路径重构出的字节级核心，xlsx/csv 双格式同链路）；
- 合并规则与 FR-2 一致：状态取"或"，新文件缺失行标记移除；
- 不随包内置演示数据，避免与真实名单混掺。

## v0.6 追加：一键导出原始内置文件（FR-12）

- 主页底部新增第 4 个按钮**「导出原始文件」**：把 rawfile 内置名单（名单.xlsx/csv）**字节级原样**保存到系统保存选择器指定位置；
- 文件名：`名单_原始_yyyyMMdd_HHMM.xlsx`（复用导出时间戳规范）；
- 目的：脱离"内网→rawfile→构建→Run"流程，随时把源文件拿回本地备份/编辑/测试，再用"导入名单"即可本地验证；
- 真机验收通过（SGT-AL10）：按钮显示正常、系统保存选择器弹出（FilePickerUIExtAbility 前台）、文件名带时间戳、PC 打开内容与内置名单一致。

## v0.5.4 追加：并发导入重复行修复（2026-08-27）

- **现象**：内网名单经内置导入后，每个名字出现两份（真机实测 2324 行 → 4648 行，相邻重复）；
- **根因**：并发导入竞态——启动自动导入进行中（内容哈希尚未落库）再次触发导入（再次拉起/手动点按），
  两次合并都基于同一旧快照 → 全部行重复插入（按 row_no 并列排序呈现为相邻成对）；
- **修复1（防复发）**：ImportService 全局导入串行队列（并发触发排队执行，前一次快照/哈希落库后再执行下一次）；
  BuiltinListService 单飞守卫（并发调用共享同一次内置导入）；
- **修复2（数据修复）**：DbHelper 一次性迁移 repairDuplicateRows——同一 row_key 且 raw_data 完全一致的组按 id 升序
  **对半去重**（并发 bug 恰好两份，保留前半、与后半成对取"或"后删除后半；**源文件自身的重复行（如"没打通再次加进来"）原样保留**；
  同键但内容不同的行不动，v0.5.3 语义不回退），app_config 标记守卫；
- **修复3（恢复被遮蔽数据）**：DbHelper 一次性迁移 restoreRemovedBatch——把行数最多的"文件中已移除"批次恢复为生效
  （并自动清理误导入的小测试批次）；配合合并快照纳入 in_file=0 行，新文件重现的行按同键"复活"且本机标记保留；
- **验证**：clean 构建 0 错误 0 警告；verify 46/46；ohosTest 增 v054_dedupe_exact_duplicates 用例；
  真机（SGT-AL10）复验：4648 → 2314 条（源文件自身含 10 组完全重复行被合并），已打 1438 全部保留，无相邻重复。

## v0.5.3 修复：导入丢行 bug

- **根因**：合并算法对"文件内同键行"做了去重（同工号/同姓名+手机的多任务行会被丢弃），导致导入后总数少于文件行数；
- **修复**：文件内同键行全部保留；本地匹配改为"同键队列一一对应"（多余本地行标记移除）；
- **恢复手段**：主页"内置名单"点击后若提示无变化，弹窗可**强制重新导入**（合并式恢复缺失行，不丢已打状态、不清除数据）；
- **诊断**：导入时记录 `merge stats`（parsed/skippedEmpty/inserts/updates/removed）到 hilog；完全空行跳过并计数；
- **黑盒比对工具**：`tools/verify/file_hash.ts` 打印文件 FNV-1a 哈希（与 APP 同一算法），用于比对内网导出文件与 rawfile 副本是否一致。
