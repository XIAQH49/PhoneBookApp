# v0.5 内置名单功能说明

| 项 | 内容 |
|---|---|
| 版本 | v0.5（基于已验收 v0.3.4 开发） |
| 需求背景 | 内网"只能进不能出"：无法联网/回传，也无法便捷地传文件到手机 → 名单文件直接打进 APP 包内 |
| 命名约定 | `entry/src/main/resources/rawfile/` 下放 **`名单.xlsx`**（优先）或 **`名单.csv`** |
| 行为 | APP 启动自动检测内置文件**内容哈希**变化 → 变化即合并导入（已打状态取"或"保留，与手动导入同一套合并规则）；主页新增"内置名单"按钮可手动导入 |

## 使用流程（每次名单更新时）

1. 把内网导出的最新表格重命名为 `名单.xlsx`（或转成 `名单.csv`）
2. 覆盖到 `entry/src/main/resources/rawfile/`（参考同目录 `README.txt`）
3. DevEco Studio **Run**（重新打包安装）
4. APP 启动 → 检测到内容变化 → 自动导入并提示"内置名单已更新并导入"
5. 名单数据即最新，已打状态保留（按工号/姓名+手机合并）

## 验证要点（真机）

| 步骤 | 预期 |
|---|---|
| rawfile 放 `名单.xlsx` → Run | 启动后 toast"内置名单已更新并导入"，列表出现数据 |
| 不改文件再次冷启动 | 无提示、不重复导入 |
| 修改表格内容（如加一行）→ Run | 自动合并导入新内容，原有已打状态保留 |
| 主页点"内置名单" | 无变化提示"无变化"；有变化则导入 |
| rawfile 无名单文件 | 点"内置名单"提示命名与路径指引 |

## 技术要点

- 变更检测：内置文件字节的 FNV-1a 哈希存 `app_config.builtin_last_hash`，与上次比较（避免每次启动重复导入）；
- 导入复用 `ImportService.importFromBytes`（从 picker 路径重构出的字节级核心，xlsx/csv 双格式同链路）；
- 合并规则与 FR-2 一致：状态取"或"，新文件缺失行标记移除；
- 不随包内置演示数据，避免与真实名单混掺。
