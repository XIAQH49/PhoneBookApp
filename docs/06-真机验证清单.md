### 0.2 实测记录：部署与权限（2026-08-25，SGT-AL10 / HarmonyOS 7.0.0.102 log）

- 未签名包安装被拒：`no signature file`（需签名）；
- CLI 签名不可用：build-profile 中口令为 DevEco 加密格式，`hvigorw` 无法解密（`Init keystore failed`），
  **签名+安装统一走 IDE Run**；
- PLACE_CALL 受限权限实测不可获得：`code:9568289 - grant request permissions failed`；
- **v0.3 决策（用户拍板）**：拨号改为 want `ACTION_DIAL` 唤起系统拨号应用，**不再申请任何权限**，
  AGC 流程整体取消，单次 IDE Run 即可完成部署（无阶段划分）。

### 0.1 T-1 性能预验证数据（Node，同一库文件，供真机对比）

| 指标 | 实测 | 判据 |
|---|---|---|
| 2000 行 × 8 列 xlsx 写出 | **70 ms**（651.7 KB） | NFR-1 ≤10s |
| 2000 行 × 8 列 xlsx 解析 | **72 ms**（热缓存 45 ms） | NFR-1 ≤10s |

复跑命令：`node --import ./tools/verify/register.mjs tools/verify/perf.ts`
结论：解析/写出性能余量 >100 倍，真机达标风险主要集中在**库加载与引擎差异**（T-1 步骤 1.2 实测确认）。

## 3. T-3 系统拨号唤起真机验证（v0.3.3：viewData+tel 直连方案）

> **实测结论链（SGT-AL10）**：
> 1. 系统电话软件 = `com.ohos.contacts`（拨号盘），注册 `ohos.want.action.viewData` + `scheme=tel` + `entity.system.home`；
> 2. shell 验证：`aa start -A ohos.want.action.viewData -U tel:13800000000 -e entity.system.home` 成功唤起（force-stop 后新 start time 回到前台）；
> 3. v0.3.2 失败的根因：预检 API `queryAbilityByWant` 需 `GET_BUNDLE_INFO` 权限且已废弃，无权限时静默失败导致永远走复制兜底；
> 4. v0.3.3：去掉预检，直接按候选顺序 startAbility（viewData+tel 优先，action.dial 兜底），全部失败才复制剪贴板。

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 3.1 | 单号码条目 → 确认框 → 拨打 | ✅ **实测通过（2026-08-25，SGT-AL10）**：系统电话软件（com.ohos.contacts 拨号盘）被唤起且号码自动填入 |
| 3.2 | 多号码条目 → 选号弹层 | 弹层出现"复制/拨打"按钮，复制后剪贴板正确 |
| 3.3 | 标记已打 | 列表该条变"✓已打"，统计更新 |
| 3.4 | 设置页关闭"拨号前确认"→ 再点拨打 | 直接唤起拨号盘（无确认框）；重新打开恢复弹框 |

**失败预案**：手机拨号界面未带出号码 → 打开设置页"拨号前去除 +86"开关重试（11 位号码）。
